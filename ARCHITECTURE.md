# Grafito architecture

Grafito is a Markdown notes vault. It has `[[wiki]]` links, tags, portfolios,
attached files, Mermaid diagrams, a relationship graph and PDF export. On top of
that it has an administrator, roles and an administration panel.

## Stack

| Layer | Technology |
| --- | --- |
| Framework | [TanStack Start](https://tanstack.com/start) (React 19, SSR and server functions) |
| Routing | TanStack Router, file-based routes in `src/routes/` |
| Styles | Tailwind CSS v4 (`src/styles.css`, themes through `data-theme`) |
| Client state | zustand (`src/app/vault/store.ts`), cached in `localStorage` |
| Authentication | Better Auth: local username and password, plus LDAP, OAuth and OIDC |
| Relational database | Postgres (`DATABASE_URL`), or PGLite embedded in `.data/pglite` |
| Search | Elasticsearch (`ELASTICSEARCH_URL`), or an index in Postgres |
| Files | MinIO / S3 (`S3_*`), or the `file_blob` table in Postgres |
| Sessions | Redis (`REDIS_URL`) holds session deadlines, or Postgres does |
| Build | Vite 8 and Nitro (`node-server` preset; `NITRO_PRESET=vercel` for Vercel) |

Every external service is optional. When its variable is missing, Grafito falls
back to the local resource listed above (see `.env.example` and
`src/server/platform.ts`).

## How it starts

- **Docker (the intended way):** `docker compose up -d --build` starts
  Postgres, Elasticsearch, Redis, MinIO and the app at `http://127.0.0.1:8080`.
  - The image is a two-stage **production build**: the first stage runs
    `npm run build`, and the final stage only carries `.output/` and runs
    `node .output/server/index.mjs`.
  - The image is about 356 MB, and the app uses about 50 MB of memory.
  - Every service has `restart: unless-stopped`.
- **Locally without Docker:** `scripts/launch-guard.mjs` blocks `npm run dev`
  unless `GRAFITO_FROM_DOCKER=1` or `GRAFITO_INTERNAL_DEV=1` is set. The second
  one uses PGLite and no external services.
- `.claude/launch.json` (not versioned) starts Vite directly, without the
  guard, for the editor preview.

| Script | What it does |
| --- | --- |
| `npm run dev` | Development server on `0.0.0.0:8080` |
| `npm run build` | `vite build` (output in `.output/`), then `db:migrate` |
| `npm start` | Runs the production build (`.output/server/index.mjs`) |
| `npm run db:migrate` | Applies `migrations/*.sql` to `DATABASE_URL`, if set |
| `npm run typecheck` | `tsc --noEmit` |
| `npm test` | `scripts/*.test.mjs`, then `src/**/*.test.ts` (Node's test runner with type stripping) |
| `npm run lint` / `format` | ESLint / Prettier |

GitHub Actions (`.github/workflows/ci.yml`) runs typecheck, lint, tests and the
build on every push and pull request, then builds the Docker image.

### Layer dependencies

```text
routes ─▶ components ─▶ app ─▶ domain
                │         │
                ▼         ▼
             server ─▶ lib (auth, db)
```

- `domain/` imports nothing from the app: only types and pure functions.
- `app/` (client) uses `domain/` and calls `server/` through server functions.
- `server/` runs only on the server. Components reach it only through
  `createServerFn`, which Vite turns into RPC calls.
- `lib/auth/*.server.ts` and `lib/auth/server.ts` must never reach the browser.

## Access flow

1. `AccessGate` calls `accessState()`. If there is no administrator yet, it
   shows "Primera vez" (first run).
2. After creating the administrator or signing in, it forces a password change
   if `mustChangePassword` is set.
3. With a valid session, `VaultApp` opens that user's vault (`openVaultFor`)
   and renders nothing until it is loaded. `VaultSync` keeps it in sync with
   the server. `SessionWatch` sends a periodic pulse and signs out when the
   configured deadline passes.
4. Server functions use `authMiddleware`, which checks the request origin
   (`isolation.server.ts`) and the session (`verify.server.ts`).

**Focus ring:** after a click, `app/input-modality.ts` sets
`<html data-modality="pointer">` and the focus ring stays off, even when a key
is pressed later. Without it, the browser draws the ring on the clicked row as
soon as any key is pressed. Tab turns the ring back on.

**One session per browser.** All tabs share it:

- The bearer token (`lib/auth/bearer.ts`) lives in `localStorage`. It is the
  fallback where the `__Host-` cookie isn't kept (plain http on a network).
- `SessionSync` writes the signed-in user id to `grafito.session-user`.
  Another tab hears it through the `storage` event. An empty value (sign-out or
  an expired session) sends every tab to the sign-in screen and drops the
  token. A different user reloads the tab, so a browser never shows two
  accounts at once.
- `lib/uuid.ts` and `lib/clipboard.ts` cover `crypto.randomUUID` and
  `navigator.clipboard`, which browsers only offer on `https://` and
  `localhost`.
- `trustedOrigins` is a function (`lib/auth/server.ts`). It accepts the
  `Origin` of a request sent to that same host (`Host`, or
  `X-Forwarded-Host`), so the server's IP and a proxy's domain work without
  being listed. `BETTER_AUTH_TRUSTED_ORIGINS` adds other sites. Better Auth's
  "Invalid origin" is shown as a message naming that variable.

## Cleanup performed (origin: the Grok App Builder template)

The project started in the Grok sandbox. Everything that belonged to that
platform rather than to Grafito was removed. Removed files were moved to
`_respaldo-grok/` with the same relative paths, so they can be recovered. That
folder is not versioned.

- Agent instructions and skills: `.grok/`, `AGENTS.md`, `startup.sh`.
- QA leftovers and artifacts: `screenshots/`, `artifacts/`, `.vercel/` (build
  output), `.tanstack/`, `.node_modules.lock`.
- Platform integrations that Grafito didn't use:
  - Grok's OAuth broker, "gate" sessions and the sign-in popup.
  - The preview bridge and its route rewriting.
  - The `app-data` and `multiplayer` connectors.
  - The PWA/branding injector (`server/`, `public/__grok/`).
  - Their test scripts.
- Dependencies that nothing imported: Radix UI, react-query, react-table,
  recharts, react-hook-form, date-fns, sonner, clsx/tailwind-merge/cva,
  playwright and others.

Code changes:

- `requireUserId` lost its "dev user" branch, which never ran because auth was
  always on.
- `password.ts` and `bearer.ts` centralize calls and token handling that were
  duplicated in `AccessGate` and `AccountScreen`.
- Shared components: `ui/TextField` (previously `Field`, in two files) and
  `chrome/AppFrame` (previously identical `Shell` / `Frame` copies in admin and
  account).
- The theme script in `__root.tsx` is generated from `THEMES`. It used to be a
  hand-made copy of the table.
- The app has its own PWA manifest and icon in `public/`, and Open Graph
  metadata in `__root.tsx`.
- Fixed: after signing in, creating the administrator or changing the password,
  the screen didn't advance until a reload.
  - Cause: `password.ts` uses a direct `fetch` (to read `set-auth-token`), but
    Better Auth only refreshes `useSession()` for calls made through
    `authClient`.
  - Fix: `$sessionSignal` is now emitted by hand.

The legacy names `__Host-grok-auth.*` (cookies) and `grok-auth.bearer-token`
(sessionStorage) were kept on purpose, because renaming them would sign out
every open session. They are centralized in `lib/auth/cookies.ts` and
`lib/auth/bearer.ts` in case they are renamed later.

## Known gaps

- PGLite isn't included in the production build (its `.wasm` isn't bundled),
  so the image always needs `DATABASE_URL`. To try it without Postgres, use
  `npm run dev` with `GRAFITO_INTERNAL_DEV=1`.
- Uploads that never reach a document (an abandoned tab mid-upload) leave
  orphan objects. A periodic sweep is on the roadmap.
- MinIO's capacity shows in the storage panel because the compose file sets
  `MINIO_PROMETHEUS_AUTH_TYPE=public`, reachable only inside the Docker
  network and on `127.0.0.1`.
- `migrations/0001_auth.sql` still has a comment that mentions Grok. Applied
  migrations aren't edited.

## Role permissions

Roles and their permissions are managed in Administration → Roles (table
`app_role_permission`). They are enforced in three layers:

1. **Server:**
   - Administration functions check the actor's permission (`allows()` in
     `server/profile.ts`).
   - Vault functions filter by `context.userId` and check write and delete
     permissions.
2. **Vault store** (`app/vault/store.ts`): every action that modifies the
   vault checks `can()` before changing anything. That covers create, edit,
   rename, delete, move, link, upload, import, edit mode and the graph. This is
   the lock that keyboard shortcuts and drag and drop can't bypass.
3. **Interface:**
   - Hidden without permission: the graph, "new note", portfolios, upload,
     link, and menu actions.
   - Disabled without permission: Edit, Split, task checkboxes and the title
     (read-only).
   - Without `notes.read`, the vault shows a notice.

`sessionPulse` returns the permissions every 12 seconds, so a role change takes
effect without signing in again. If editing or the graph is revoked, the view
falls back to Read and the graph closes by itself. The initial administrator
always has every permission, and their role can't be changed (in the interface
or on the server).

## Sharing

Every note and portfolio is **private** by default. If their role has
`notes.share`, the owner can change that with "Compartir…" (Share…), from the
editor's "more actions" menu or by right-clicking in the directory.

| Visibility | Who sees it | How |
| --- | --- | --- |
| Private | Only the owner | No row in `share_item` |
| Shared | The chosen users and organizations, with `access` = `read` or `edit` | In their directory, under the **Compartidos conmigo** root (`vault/SharedSection`). Items open in the main area. `/compartidos` remains for direct links. |
| Public | Anyone with the link, without a session | `/p/<token>` (random 192-bit token), always read-only |

- **Editing:** with `edit` access, `editSharedDoc` writes to the owner's vault
  through `updateNote` (with the editor as author), only if the note is still
  at the version the editor opened (`baseUpdatedAt`). Otherwise it returns the
  current version, and the viewer offers to keep theirs or overwrite. The
  editor's role also needs `notes.edit`. The owner's browser receives the
  change through sync.
- Sharing a portfolio includes its sub-portfolios and documents.
- The directory and the editor mark shared (👥) and public (🌐) items, including
  ones that inherit the status from a portfolio.

Shared content is read straight from the owner's server vault (`vault_doc`,
`vault_portfolio`), so edits and the owner's changes show up immediately. The
older **published copy** (`published_doc`, `published_portfolio`) is only a
fallback for owners without a server vault:

- **Publishing:** `ShareMirror` refreshes it about 2.5 seconds after each change
  by the owner.
- **Coverage check:** the server recomputes what each item covers
  (`domain/share.ts`) and drops anything extra the client sends.
- **Revoking:**
  - Making an item private deletes its copy.
  - Deleting a shared note or portfolio removes its share item.
- **Access:** the server only serves an item to its owner, to its grantees,
  or, if it is public, to whoever has the token.

Limitations:

- Recipients see the last version the owner published from their browser.
  Edits made offline are published when the owner reconnects.
- Shared files are served from storage through signed links (see
  [Files](#files)).

## Organizations

Administration → Users and permissions → Organizations (`orgs.manage`
permission).

- **Hierarchy:** organizations can have sub-organizations, with no cycles.
  Deleting one deletes its sub-organizations.
- **Members:** each organization has its own members.
- **Sharing:** when a note or portfolio is **shared** with an organization, its
  members and the members of all its sub-organizations see it. The server
  resolves this by walking up from the user's organizations to the roots (a
  recursive query in `server/share.ts`).

## External authentication

Administration → Authentication (`auth.manage` permission). Each provider has
three settings:

- Whether it is enabled.
- The role for new accounts (Member by default).
- The allowed email domains (empty means any).

Secrets are stored in `auth_provider` and never go back to the browser. Saving
with an empty secret keeps the previous one.

| Provider | How people sign in | Details |
| --- | --- | --- |
| LDAP / Active Directory | The «Directorio (LDAP)» tab on the sign-in screen | The service account searches with the filter (`{{username}}`, escaped), then binds with the person's DN. Has a «Probar conexión» (test connection) button. |
| OAuth: Google, GitHub, Microsoft | A «Continuar con…» button | Better Auth social providers. The panel shows the callback URL to register. |
| SSO (OpenID Connect) | A button with the configured label (for example «Keycloak») | `genericOAuth` with discovery (`<issuer>/.well-known/openid-configuration`) and PKCE. Has a «Probar emisor» (test issuer) button. |

On first sign-in, `provision.server.ts` creates the account with the default
role and sets `app_user_role.source` to the provider. The Users list shows it as
a badge.

The Users list also shows each person's first sign-in and last activity
(`app_profile.first_login_at` and `last_seen_at`). `requireLease` updates them
on authenticated requests, at most once a minute per person.

An external account **never** takes over an existing account just because the
email matches. Better Auth uses `disableImplicitLinking`, and LDAP rejects it
with «Ya existe otra cuenta con ese correo» ("another account already uses that
email"). LDAP accounts without an email use `<uid>@ldap.grafito.app`.

The contact email of an external account is the provider's. The
`session.create.after` hook calls `syncExternalEmail`, which copies it to
`app_profile.contact_email` on every sign-in (empty for the synthetic
addresses). Account → Correo shows it read-only. The server functions that
write that field (`saveMailPreferences`, `updateAccount`, `updateVaultUser`)
skip it when `app_user_role.source` isn't `local`.

To test locally, use any reachable LDAP directory or OpenID Connect provider.
`dev/auth-test/` has a sample Keycloak realm and LDAP users. The test services
themselves aren't in `docker-compose.yml`: they live in a local test compose
that isn't versioned.

**Lockfile:** after `npm install <package>` with a different npm than the
image's (Node 22 / npm 10), regenerate `package-lock.json` like this so the
`Dockerfile`'s `npm ci` doesn't fail:

```bash
docker run --rm -v "$PWD:/app" -w /app node:22-bookworm-slim npm install --package-lock-only
```

## Server-side vault and sync

Since migration 0008, each user's vault lives in Postgres (`vault_doc`,
`vault_portfolio`). The browser keeps a copy so it can open instantly.
`app/vault/sync.ts` syncs the two:

- **Revisions:** every server-side change gets the user's next revision
  (`vault_state.revision`). Deletions stay as tombstones.
- **Merging:** the browser remembers the last revision it received and a
  fingerprint of each document as last synced. It pulls what is new and pushes
  what changed locally.
  - **Notes:** the first local edit since the last sync records `base`, the
    server version it starts from (`mark` in `app/vault/store.ts`). The push
    carries it.
  - If the server's note changed since `base` (a person it's shared with, the
    AI, another tab), `pushChanges` merges both with `merge3`
    (`domain/vault/merge.ts`): a line-based three-way merge where lines changed
    on only one side are taken from that side.
  - If both changed the same lines, nothing is written. The note comes back in
    `conflicts`, the editor shows **Usar la suya** / **Guardar la mía**
    (`keepTheirs` / `keepMine` in `sync.ts`), and the note isn't pushed until
    then.
  - A merged note is pulled again, so every tab ends up with the same text.
  - Files, and notes cached before `base` existed, keep "the newest wins".
- **Shared notes:** a person with edit access saves through `editSharedDoc`,
  sending `baseUpdatedAt` and `baseContent`. If the note changed meanwhile, it
  is merged the same way, or reported as a conflict.
- **Who is editing:** each open editor (in Editar or Dividir mode, or a shared
  note being edited) calls `notePresence` every 10 seconds
  (`app/presence.ts`). `server/presence.ts` keeps it in memory for 30
  seconds, so with several Grafito instances each one only knows its own
  callers.
- **When it syncs:**
  - When the vault opens.
  - 1.5 seconds after each change.
  - Every 20 seconds.
  - When the tab regains focus.
  - Right after the AI changes something.
- **First time in a browser:**
  - If the server already has the vault and the browser only has the sample
    one, the server's vault is adopted.
  - If the browser had saved notes (older versions), the two are merged and
    whatever is missing is uploaded.
- **Permissions:** the server rejects changes from users without write
  permission, and deletions without the delete permission.

## Version history and trash

- **Versions** (`server/history.ts`): `writeDoc` records a version whenever a
  note's title or text changes, whether the change comes from the owner's
  browser, a shared editor, the API or the AI.
  - Consecutive changes by the same author within 10 minutes are merged into
    one version.
    - For Office files, only the editor's autosaves are merged
      (`vault_doc_version.autosave`, migration 0014). Each save the person
      makes keeps its own version.
  - A restore always creates its own version, so it can be undone.
  - Each note keeps its latest 200 versions.
- **Trash:** a deletion sets `deleted` and `deleted_at` and keeps the content.
  Browsers still receive it as a tombstone.
  - `restoreFromTrash` brings the note back with a new revision, and recovers
    deleted parent portfolios (or moves the note to the root if they are
    gone).
  - `purgeTrash` clears the content and the versions.
  - Items older than 30 days are purged when the trash is listed or something
    is deleted.
  - Legacy tombstones (from before migration 0010) have no `deleted_at` and
    never appear in the trash.

## Files

File bytes no longer travel inside notes. A file document carries
`{ name, mime, key, size }`; the bytes live in MinIO / S3 under
`vault/<userId>/<uuid>`, or in `file_blob` when no object storage is
configured.

- **Upload:** the browser sends the file to `/api/files/uploads` in 8 MiB
  parts. That becomes an S3 multipart upload, or appends to the Postgres row.
  The upload is capped by `GRAFITO_MAX_UPLOAD_MB` (100 MB with S3, 20 MB
  without). The client then creates the document with the returned key, and
  sync sends it. The server rejects keys outside the user's own prefix.
- **Viewing and downloading:** the app asks the server for **signed links**
  (`server/file-links.ts`): an HMAC over document, owner, expiry (one hour)
  and download flag. The permission check happens when the link is issued
  (`notes.read` to view, `files.download` to download; for shared content, the
  share grant).
  - Links work in `<img>`, `<iframe>` and `<video>` even without the session
    cookie (plain http outside localhost).
  - Public links use the share token instead.
  - API clients can use their token or session directly.
- **Response headers** (`fileResponse`):
  - Images, PDF, audio and video are served inline. Everything else is an
    attachment.
  - SVG, HTML, XML and JavaScript are always attachments with a
    `sandbox` CSP, so an uploaded file can't run script in Grafito's origin.
  - All files are served with `nosniff` and support `Range`.
- **Legacy files:** older vaults kept files as data URLs (`file_data`, plus the
  browser cache).
  - On a user's first sync, `migrateLegacyFiles` moves them to storage and
    bumps their revision, so browsers drop the cached bytes.
  - A browser that still sends a data URL (old cache, sample notes) has it
    stored by `storeIncomingFile`.
- **Deletion:** purging from the trash deletes the object. Deleting a user
  deletes their objects.
- **Backups:** `pg_dump` covers documents and, without S3, the bytes. The
  `backup-files` service mirrors the bucket into `./backups/files` without
  deleting, so older dumps still find their files.

## Office editor (WOPI)

On by default in `docker-compose.yml` (the `collabora` service). It is
turned off by setting `COLLABORA_URL` to empty (`server/office.ts`,
`docs/OFFICE.md`).

- **Gateway** (`docker/gateway.conf`, the `gateway` service on port 8080):
  nginx sends `/browser/`, `/hosting/` and `/cool/` to Collabora and the rest
  to the app. With `COLLABORA_URL=same-origin` the editor URL is the page's
  own origin plus Collabora's path, so the CSP needs nothing beyond `'self'`.
  The gateway rewrites Collabora's `data-host` and CSP to the page's address
  (`ws://` or `wss://`), taken from the `Origin` of the POST that opens the
  editor. Docker DNS is resolved per request, so the app and Collabora can be
  recreated or stopped without restarting it.
- **Own address** (any other `COLLABORA_URL`): `server/office-reach.ts`
  derives the editor host and reports settings the browser would block.

- **`officeSession`** (`office.functions.ts`):
  - Checks access (own file, or a share via `editableTarget` /
    `grantedDocOwner`).
  - Signs a 10-hour token with `signToken` (`server/file-links.ts`). The token
    carries document, owner, editor, write flag, browser origin and share id.
  - Returns the editor URL from Collabora's `/hosting/discovery`, rewritten to
    the page's origin (`same-origin`) or the public `COLLABORA_URL`, with
    `WOPISrc` and `lang`.
- **WOPI endpoints:**
  - `routes/wopi/files/$id.ts` implements `CheckFileInfo`.
  - `$id.contents.ts` implements `GetFile` and `PutFile`.
  - `PutFile` stores a new object, calls `replaceFile` (`server/vault.ts`) and
    records a file version (`recordFileVersion`; the original is the
    baseline).
  - When editing through a share, the share is checked again on every save.
- **Client:** `components/vault/OfficeEditor.tsx` opens the editor in an iframe
  through a POST form. The CSP allows Collabora's origin in `frame-src` and
  `form-action` (`lib/security-headers.ts`).
- **Browser state:** a pushed file document can't change its storage key.
  Only the server changes file contents.

## Languages (i18n)

The interface is in Spanish and English.

- **`domain/i18n.ts`:** `translate(locale, text, vars)`. The Spanish text is
  the key, and `domain/i18n/en.ts` is the English catalog.
  - `{0}`-style variables fill in values.
  - The same keys work as patterns to translate messages the server sends
    already assembled (errors, log entries, AI tool chips).
  - Missing translations fall back to Spanish.
- **`app/i18n.ts`:** the client provides `t()`, `useLocale()`, `setLocale()`
  and `intl()` (date and number formats).
  - The language is stored in the `grafito-locale` cookie.
  - `routes/__root.tsx` reads that cookie on the server and the client
    (`createIsomorphicFn`), so the first render matches and hydrates cleanly.
  - Changing the language remounts the app (`<Outlet key={locale}>`).
- **Account preference:** Account → User preferences saves it in
  `app_profile.locale` (migration 0013). `AccessGate` applies it after
  sign-in.
- **Server:** messages stay in Spanish and are translated where the client
  displays them (`t(error)`).
- **Not translated:** content (notes, including the sample notes) and
  technical names.
- **Adding a language:**
  1. Add it to `Locale` and `LOCALES`.
  2. Create its catalog next to `en.ts`.
  3. Register the catalog in `catalogs`.

## Designs and themes

The look has two independent axes:

- **Theme** (`app/theme.ts`): colors, fonts and the theme's own radii.
  - Ten themes, chosen per browser.
  - Applied as `<html data-theme>` by the boot script, with no flash.
- **Design** (`domain/design.ts`), for the whole installation: `modern`
  («Cristal», the default; it was called «Moderno», and the id stays so stored
  settings keep working) or `classic` («Clásico»).
  - The administrator chooses it in Administration → Appearance → Design. It
    is stored in `app_setting.ui_design` (`server/design.ts`, cached 15 s).
  - The root route reads it on the server (`createIsomorphicFn`) and renders
    `<html data-design>`, so the first paint is already correct.

**Classic** is the base interface. **Cristal** is a separate CSS layer,
`src/design-modern.css`, active only under `html[data-design="modern"]`.

- **What Cristal changes:** shapes, depth, spacing and layout:
  - floating glass panels,
  - pill controls,
  - an accent glow,
  - a segmented Edit / Split / Read control,
  - blurred overlays.
- **What it keeps from the theme:** colors and fonts always come from the
  theme's tokens, so every theme works in both designs.
- **No `@layer`:** the rules sit outside any `@layer`, so they win over
  Tailwind utilities without `!important`.
- **Targets:** components expose stable `data-ui` markers: `shell`, `topbar`,
  `panes`, `sidebar`, `rail`, `workspace`, `editor`, `modebar`, `context`,
  `context-slot`, `inspector`, `dialog`, `popover`, `overlay`, `auth`,
  `auth-card`, `chat`, `fab`, `tabbar`, `toast`. Use these instead of utility
  classes when styling a design.

**Text and cursors** (`styles.css`, both designs):

- Reading text can be selected and copied.
- The pointer is the arrow, except in editable fields (text cursor) and on
  controls (hand).
- The caret is hidden everywhere except in editable fields.
- Buttons, menu items, switches and draggable rows aren't selectable, so
  clicking them doesn't start a selection.
- **No stray text cursor** (`app/blank-click.ts`, installed once by the root
  route): browsers move the text selection to the nearest spot on any click,
  often the end of a field or its label, and some draw a blinking bar there.
  - A click on blank space (top bar, gaps between panels or between form
    fields, a dialog's background) or on a text field's label doesn't move the
    selection and releases the focused field. Labels of text fields no longer
    focus them; checkboxes and the pill-shaped search fields
    (`label[data-field]`) still do.
  - When focus moves to something that isn't a text field (a button, a
    selector), a caret left parked between elements is removed.
  - Opening the vault clears a stray caret carried over from another screen.
  - Reading text (`article`), drawings, draggable rows and scrollbars are left
    alone, so text can still be selected.

## Security headers

`src/start.ts` registers a request middleware that adds these headers to every
response (`lib/security-headers.ts`):

- **Content-Security-Policy:**
  - Scripts and styles come from the same origin, plus inline (TanStack Start
    inlines its SSR state and the theme script).
  - Images can be `https:`, `data:` or `blob:`.
  - Frames can be `data:` or `blob:` (PDF previews).
  - `object-src 'none'`, `frame-ancestors 'none'`.
- **`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`.**
- **`Referrer-Policy`, `Permissions-Policy` and
  `Cross-Origin-Opener-Policy`.**

Moving to nonces is on the roadmap.

## REST API

Authentication:

- `Authorization: Bearer gft_…`: a personal token from Account → API. Only its
  SHA-256 hash is stored.
- Or the browser session, from the same site only.

Every operation checks the role's permission.

| Method and path | Permission | What it does |
| --- | --- | --- |
| `GET /api/v1/me` | — | User, role and permissions |
| `GET /api/v1/portfolios` | `notes.read` | Portfolios |
| `POST /api/v1/portfolios` `{ name, parentId? }` | `portfolios.manage` | Creates a portfolio |
| `GET /api/v1/notes?portfolio=<id\|root>&q=<text>&limit=<n>` | `notes.read` | Notes and files (without content) |
| `POST /api/v1/notes` `{ title, content?, portfolioId? }` | `notes.create` | Creates a note |
| `GET /api/v1/notes/:id` | `notes.read` | The note, or for a file its metadata and its text if it is a text file |
| `PATCH /api/v1/notes/:id` `{ title?, content?, portfolioId? }` | `notes.edit` | Updates a note. Renaming updates `[[links]]`. |
| `DELETE /api/v1/notes/:id` | `notes.delete` / `files.delete` | Deletes it |
| `GET /api/v1/notes/:id/file` | `files.download` | Downloads the file |

Errors: JSON `{ "error": "…" }` with status 400, 401, 403, 404 or 409.

## AI assistant

- **Administration → AI** (`ai.manage`): only turns each provider on or off.
- **Account → AI** (`ai.use`): each person connects the allowed providers.
  - Cloud providers use the person's own key, against the official URL.
  - Ollama and LM Studio use the address of **the person's own instance**,
    with an optional key.
  - The connection is tested before saving.
  - The key is encrypted (AES-256-GCM with `GRAFITO_ENCRYPTION_KEY`). Only its
    last 4 characters are shown.
- **Self-hosted addresses** (`server/ai/local-url.ts`): the server makes the
  call, so these are restricted:
  - Only `http(s)` without credentials is accepted.
  - Grafito's own server (`localhost`, `127.x`, `::1`, `0.0.0.0`) is rejected.
  - Exception in Docker: with `GRAFITO_LOCALHOST_ALIAS` (set to
    `host.docker.internal` in `docker-compose.yml`, plus
    `extra_hosts: host-gateway`), a `localhost` address points to the host
    machine instead. The address is stored as typed, and the server calls the
    alias. This lets a person use an Ollama or LM Studio installed on the same
    machine.
  - The deployment's internal services (`postgres`, `redis`, `elasticsearch`,
    `minio`, `app`…) are rejected.
  - The address is validated again on every use, and adapters don't follow
    redirects.
  - Other LAN addresses are accepted, since that is the use case. If that isn't
    acceptable in your deployment, disable Ollama and LM Studio.
- **Chat:**
  - Opens from the floating button in the vault or **Ctrl+B**. Inside the note
    editor, Ctrl+B stays bold, and Esc closes the chat.
  - With no provider connected, it says so and links to Account.
  - With a provider but no model, it asks you to pick one.
  - **Model picker:** a compact button under the message box. It opens upward
    with the models of each connected provider.
  - **Conversations** (`server/ai/conversations.ts`, table `ai_conversation`,
    migration 0015):
    - Each one is saved after every answer, with a title taken from its first
      question. Each person keeps up to 200 conversations.
    - The tab remembers which conversation is open.
    - **History** lists them, opens one or deletes it. **New conversation**
      starts another.
  - **Context:** each conversation sends only its own turns to the model: the
    last 30, up to about 24,000 characters (`app/ai-chat.ts`).
  - **Minimize:** a click outside the panel (on desktop) shrinks it toward its
    button in 200 ms. Opening animates the other way. The draft lives in the
    chat store, so it survives.
  - **Profiles** (`server/ai/profiles.ts`, table `ai_profile`, migration
    0017):
    - Each person's own presets: a name, instructions and `read_only`. Up to
      30 per person.
    - The chat sends the chosen profile's id (`profileId`) with each message.
      `runAgent` loads it for that user and adds its instructions after the
      assistant's own, so they shape tone, format and focus.
    - A read-only profile drops the tools marked `writes` (`create_note`,
      `update_note`, `create_portfolio`) on top of what the role allows.
    - A deleted profile is ignored, and the chat falls back to **General**.

| Provider | Protocol | Address | Key |
| --- | --- | --- | --- |
| ChatGPT (OpenAI) | Chat Completions | `https://api.openai.com/v1` | `Authorization: Bearer` |
| Claude (Anthropic) | Messages (`tool_use` / `tool_result`) | `https://api.anthropic.com` | `x-api-key` and `anthropic-version` |
| Grok (xAI) | Chat Completions | `https://api.x.ai/v1` | Bearer |
| Gemini (Google) | `generateContent` (`functionCall` / `functionResponse`) | `https://generativelanguage.googleapis.com/v1beta` | `x-goog-api-key` |
| DeepSeek | Chat Completions | `https://api.deepseek.com` | Bearer |
| Kimi (Moonshot) | Chat Completions | `https://api.moonshot.ai/v1` | Bearer |
| Ollama | Native `/api/chat` | Each user's instance | Optional |
| LM Studio | Chat Completions | Each user's instance (`…/v1`) | Optional |

The agent (`server/ai/agent.ts`) alternates model calls and tool calls, for up
to 8 steps.

- **Tools:** only those the role allows, out of `list_portfolios`,
  `list_notes`, `search_notes`, `read_note`, `create_note`, `update_note` and
  `create_portfolio`. The read and edit tools accept an id, an exact title
  or a part of a title that matches only one document. Portfolios are found
  by id, name or path («Proyectos › Atlas»). On a miss, the tool returns the
  close matches or the list of portfolios, so the model can retry.
- **Files:** `read_note` returns the text of uploaded files
  (`server/files.ts` → `fileText`): plain text, Office and OpenDocument
  (`server/office-text.ts`, a small ZIP reader without dependencies) and PDF
  (`unpdf`). Images and scanned PDFs give no text.
- **Response:** streamed as NDJSON. The chat shows each tool used, and you can
  click one to open the note.

Ollama and LM Studio aren't in the compose. Run them outside it with their
port exposed. Enable the provider in Administration → AI, then connect it in
Account → AI, for example with `http://localhost:11434` or
`http://localhost:1234/v1`.
